# M2 local API: rulings and deferred minors

Every decision the executor made on the owner's behalf while carrying out `2026-10-27-m2-local-api.md`, in order, each with what it costs if wrong; then every review finding deferred as Minor. Copied from the plan's ledger before its workspace was deleted. Commit hashes before 2026-11-16 predate the author-email rewrite.

## Rulings

- Task 2: Ruling: added Store.transaction(), a public name for the existing write transaction — redeeming a code must count tries and consume the code atomically, or two racing devices could both win — cost if wrong: none.
- Task 3: Ruling: added Store(any_thread=True), used only for the per-request connection — FastAPI may enter a dependency and run the route on different worker threads, and sqlite3 refuses that by default; only one thread uses the connection at a time — cost if wrong: a misuse would no longer raise ProgrammingError for that connection.
- Task 3: Ruling: shared dependencies live in engine/api_deps.py, not api.py — the routers of Tasks 4-8 import them and api.py imports the routers, so one file would be an import cycle — cost if wrong: none.
- Task 3: Ruling: no /docs, /redoc or /openapi.json routes (openapi_url=None); app.openapi() still builds the document for Task 10 — nothing but this app reads the API, and a route listing is one less thing exposed — cost if wrong: none.
- Task 3: Ruling: the Tailscale login header is RFC 2047 decoded before comparing — Tailscale encodes non-ASCII logins that way, and an owner with such a login would otherwise be locked out — cost if wrong: none.
- Task 5: Ruling: search and the opportunity filter compare through a fold() SQL function (casefold), not plain LIKE — SQLite LIKE ignores case for ASCII only, and the mail is partly Vietnamese ("đại học" must find "Đại học"); it scans rows only when q is given — cost if wrong: a few ms on a search at 5,000 rows.
- Task 7: Ruling: merged main (IMAP) into m2-local-api first (bf8ab88): config.py keeps both sides' fields (api, dashboard, then gmail_address last); test_engine_jobs keeps both imports; dummy_ctx's positional Config fixed (c34cd9b) — the switch removed credentials_file — cost if wrong: none, 883 tests passed after the merge
- Task 7: Ruling: settings' gmail.signed_in uses gmail_imap.token_fingerprint, not gmail_client's (deleted by the IMAP switch); the plan text is corrected — cost if wrong: none
- Task 7: Ruling: POST /api/settings/rescore is open to paired devices too (Authorized, not LocalOnly) — the plan doesn't restrict it, rescoring is free and reversible — cost if wrong: the laptop can trigger a rescore
- Task 7: Ruling: the spend report lists only days with calls (no zero rows), the items report lists every week asked for (empty dicts for quiet weeks), needs_action is newest first, upcoming_deadlines is uncapped and earliest first — the plan leaves these open; the dashboard fills chart gaps — cost if wrong: small shape changes in M3
- Task 8: Ruling: the brief's fixtures (client, password, bus, ctx, store, device_key, live_server) map onto the existing Api helper; live_api in api_helpers runs uvicorn on a free port that is also the config's [api] port, so the Host check lets local requests in — cost if wrong: none, test-only
- Task 8: Ruling: the stream copies each event without "kind" instead of popping it — EventBus hands the same dict to every subscriber, so pop crashed a second open stream (KeyError, test_every_open_stream_gets_each_event RED→GREEN) — cost if wrong: none
- Task 8: Ruling: the device re-check runs device_for_key in a worker thread on the stream's own request connection — it may wait up to 10 s for the write lock to note "last seen", which must not block the event loop; an open stream keeps the device's last_seen_at fresh — cost if wrong: one SQLite connection held per open stream
- Task 8: Ruling: added test_every_open_stream_gets_each_event and test_a_paired_device_keeps_its_stream_while_its_key_works beyond the brief; 7/7 mutants killed; file run 5x green — cost if wrong: none
- Task 9: Ruling: shutdown order — run_engine's finally stops the server first, then (on a failed start) sets stop and joins the engine thread in 0.2 s slices; on the normal path the engine thread has already finished its job when wait_until_stopped returns, so the API answers while the last job finishes, and event streams end at once because ctx.stop is the engine's stop — the spec is silent on order — cost if wrong: the dashboard can read for a few seconds while "Stopping after the current job" shows
- Task 9: Ruling: uvicorn runs with access_log=False (beyond the plan's Config args) — request URLs carry search terms and logs hold no local data; with log_config=None they were already dropped, this keeps it so if logging is ever configured — cost if wrong: none
- Task 9: Ruling: ApiServer's thread target wraps server.run and swallows SystemExit — uvicorn sys.exit(3)s its thread when it can't bind; start() reports that as the ConfigError; without it pytest flagged an unhandled thread exception — cost if wrong: none
- Task 9: Ruling: the engine thread starts its jobs before the API is up (ApiContext needs engine.holder/bus, built in that thread); a busy port then stops the engine after its current job — rare, and no paid reply is thrown away — cost if wrong: one mail check or extraction runs on a start that then fails
- Task 9: Ruling: tests — write_config gives every runtime test a free [api] port so the suite never collides with a running engine on 47615; the Idle doubles gained holder/bus; ApiServer tests use port 0 with an explicit Host header; added test_a_stuck_server_is_forced_to_exit, test_the_launch_password_is_shown_only_with_dev, test_a_busy_api_port_stops_the_start_and_frees_the_lock, test_engine_dev_reaches_the_engine beyond the brief; 13/13 mutants killed; socket files 5x green — cost if wrong: none
- Task 9: Ruling: the existing tests that send Tailscale-User-Login with the launch password on a local Host stay as they are — the new signal is X-Forwarded-*, which serve always sets; the login header alone (a forging local process) still goes through the login check — cost if wrong: none

- Task 10: Ruling: app/package-lock.json committed (the plan lists only package.json) — exact, reproducible installs; every package resolves from registry.npmjs.org; installed with --ignore-scripts (neither tool needs install scripts) — cost if wrong: none

- Final: Ruling: no 503 mapping for "database is locked" on API write routes — with the lock no longer held across downloads, writes wait milliseconds; a rare >10 s wait still returns a bare 500 — cost if wrong: an unfriendly error in a rare case, which M3 shows generically
- Final: Ruling: half-open TCP through tailscale serve keeps a stream's subscriber until tailscaled gives up (minutes) — bounded queue, no stream lifetime in the spec — cost if wrong: one stale subscriber of at most 100 events for a few minutes
- Final: Ruling: each open stream holds one anyio worker token (q.get with a 1 s timeout) rather than the spec's call_soon_threadsafe handoff — about 4 streams in normal use; 40 still answered health in 0.89 s — cost if wrong: worker exhaustion only at dozens of streams

- Final: Ruling: the launch-password rule relies on tailscale serve's HTTP mode (it always sets X-Forwarded-*); TCP or TLS-terminated serve modes would leave Host as the only signal — the README prescribes `tailscale serve --bg 47615` — cost if wrong: only if the owner changes serve mode and the password leaks

- Final: Ruling: the starred tab and Today's starred count include dismissed or expired starred items, and upcoming_deadlines leaves out applied ones — the plan's definitions; M3 can refine the UX — cost if wrong: small count differences in M3
- Final: Ruling: a stream opened after the first Ctrl+C returns 200 and ends at once (no 503) — consistent with Task 9's ruling that reads are served while the last job finishes; M3's client backs off — cost if wrong: a few quick reconnects during a stop
- Final: Ruling: revocation past 20 s was possible only through the busy last_seen wait — fixed with busy_timeout 0 — cost if wrong: none
- Final: Ruling: unhandled route exceptions and uvicorn errors go to stderr (logging.lastResort), not engine.log — spec section 9's log rule is written for jobs, and nothing secret reaches either — cost if wrong: a route crash leaves no line in engine.log
